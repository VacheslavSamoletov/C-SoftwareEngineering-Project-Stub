# Монте-Карло для оценки европейского опциона (C++17)

Учебный проект курса «Программная инженерия и C++» (Вега Институт).
Моделирование цены актива геометрическим броуновским движением (GBM)
и оценка опциона методом Монте-Карло. Не усложняй, делай просто.

## Текущий этап — ДЗ 1 (дедлайн 28.10.2026)

Нужна только функция генерации траектории GBM плюс тесты, бенчмарк,
Doxygen-документация и CI. Опцион, payoff, оценщик Монте-Карло,
адаптеры ввода-вывода сейчас НЕ делать.

## Принятые решения

- Шаг GBM — точная (логарифмическая) схема:
  S[k+1] = S[k] * exp((mu - sigma^2/2) * dt + sigma * sqrt(dt) * Z), dt = T / n_steps.
  Схему Эйлера не реализовывать.
- Случайные числа: `std::mt19937_64` + `std::normal_distribution<double>`,
  оба создаются локально внутри функции из seed. Никакого глобального состояния.
- Сигнатура:
  `std::vector<double> generate_gbm_path(double s0, double mu, double sigma, double t, std::size_t n_steps, std::uint64_t seed);`
  Возвращает n_steps + 1 значений, первое — s0. При n_steps == 0 возвращает {s0}.
  При s0 <= 0, sigma < 0 или t <= 0 бросает `std::invalid_argument`.
- Ядро — статическая библиотека `mc_core` в `src/core/`, пространство имён `mc`.
  `main` и тесты линкуются к ней.
- GoogleTest и Google Benchmark подключаются через CMake FetchContent.
- Тесты воспроизводимости сравнивают два запуска между собой и не зашивают
  конкретные числа (алгоритм `std::normal_distribution` зависит от компилятора).

## Структура папок

- `src/core/` — ядро (библиотека)
- `src/main.cpp` — точка входа
- `tests/` — тесты (GoogleTest)
- `benchmarks/` — бенчмарк (Google Benchmark)
- `docs/` — документация, `docs/adr/` — архитектурные решения

## Команды

Сборка:

```
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

Тесты:

```
ctest --test-dir build --output-on-failure
```

Бенчмарк:

```
./build/benchmarks/gbm_bench
```

Документация (HTML в `build/doxygen/html`):

```
doxygen Doxyfile
```

## Правила кода

- Ядро не зависит от ввода-вывода. Чтение файлов, консоль и сеть — только снаружи ядра.
- Никакого ручного `new`/`delete`. Используй `std::vector`, `std::unique_ptr` и т.п.
- Новый код идёт вместе с тестом в `tests/`.
- Публичные функции ядра документируются Doxygen-комментариями
  (`\brief`, `\param`, `\return`, `\throws`).
